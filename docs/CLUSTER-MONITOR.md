# 右侧集群资源监控

控制页“右侧内容”可在 DeepSeek 余额与集群资源之间切换。集群模式在原右侧区域显示四个 Slurm 节点、CPU 已分配/总核数、内存已分配/总 GB、GPU 已分配/总卡数，以及最近成功更新的时间。切回余额不会清除余额配置或布局。

## 连接与刷新

使用 Windows OpenSSH 中已经配置的主机别名，例如 `hpc-login`，连接到集群登录节点。先在自己的终端确认 `ssh hpc-login` 能正常使用已有认证；本应用只使用该别名，不接收或保存密码、私钥，也不会自动接受未知主机密钥。

刷新间隔默认 60 秒，可选 15、30、60、120、300、600 秒或自定义 15–3600 秒。保存后作为下次启动的默认间隔。切换到集群模式会在后台更新，余额模式停止集群轮询；“立即刷新”也有最短间隔保护。每次仅通过登录节点执行固定的只读 `scontrol show nodes --oneliner`，不连接计算节点、不提交计算作业、不修改调度器。

CPU 总量取 `CPUTot`，已分配取 `CPUAlloc`；内存取 `AllocMem` / `RealMemory`，按 1024 MB 换算为显示中的 GB（即 GiB 口径），最多一位小数；GPU 优先取 TRES 的通用 GPU 数，避免与型号明细重复相加。确认 GPU 已分配和总量均为零时，屏幕隐藏该节点的 GPU 行；未知 GPU 数据仍保留等待提示。所有数值是调度器分配量，不是瞬时 CPU 利用率、实际 RAM 用量或 GPU 忙闲率，也不是个人作业配额。系统保留与分区约束仍可能影响实际可申请资源。字段说明参见 [Slurm scontrol](https://slurm.schedmd.com/scontrol.html)。

节点状态文字和圆点按 CPU 已分配比例着色：低于 40% 为绿色，40% 至不足 70% 为黄色，70% 及以上为红色。离线、维护、排空或无有效 CPU 数据的状态保持中性颜色；颜色不覆盖调度器返回的状态含义。失败保留的最近可信数据仍沿用原色，更新时间与待检查提示用于判断新鲜度。

集群标题、节点名、状态和更新时间保持清晰的字号层级。四个节点的 CPU、内存、GPU 标签与数字共用一个默认资源字号，不因有无 GPU 改变。长数字、窄面板或较大的整体字体比例需要缩小时，四个节点一起适配，避免单节点文字忽大忽小和数字重叠；已有副本中用户明确设置的独立字号与位置覆盖仍然保留。

## 失败和本地保留

SSH 超时、认证失败或节点数据不完整时，保留最近成功的四节点数据与其原始更新时间，并显示小型待更新提示；不能用请求尝试时间冒充数据更新时间。没有可信历史时显示等待数据，不伪造零资源。启动时先加载本地最近成功缓存，再后台查询。

配置保存在程序外的用户设置中：`right_panel_mode`、`cluster_ssh_host`、`cluster_refresh_seconds`。节点缓存文件为 `cluster-last-good.json`，仅保存节点名、状态、数字、时间和主机别名的摘要，不保存 SSH 原始输出、地址、密钥、作业或用户列表。变更别名后不会把旧集群的数据当成新集群数据。缓存纳入本地安装备份，不能加入 Git 或公开发行包。

## 维护与模板

`agent_dashboard/cluster.py` 负责固定查询、解析、单线程调度和缓存；`settings.py` / `web.py` 提供配置；`app.py` 切换快照与帧缓存身份；`render.py` 使用同一套渲染器输出三个主题。`cluster` 与 `cluster.node_1` 至 `cluster.node_4` 是可编辑语义组，按排序后的节点槽位稳定定位。UI JSON 只保存外观，不导出连接别名或资源快照。旧账户和角色元素 ID 不变。

示例、测试与公开截图必须使用 `node-01` 等合成节点，不写入真实主机地址、连接别名、账户资料或集群采样值。常规测试 mock SSH；真实查询只能验证只读接口，不应为了测试重复提交任务或部署服务。

发布只包含 Git 白名单中的源码、文档和合成素材。账户资料、SSH 配置、连接别名、节点缓存和本地布局均保留在用户数据目录，不导入源码或安装包；推送前扫描待提交文件，构建后仅发布干净 CI 生成的文件。
