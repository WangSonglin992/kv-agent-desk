# Windows release builds

The Windows release workflow builds on a clean GitHub-hosted Windows runner with Python 3.12. It installs the pinned requirements-build.lock.txt, checks the tracked public tree, runs the unit suite, and performs source, packaged-executable, and Setup install/reinstall smoke tests. Runtime smoke tests use isolated paths under RUNNER_TEMP; the Setup smoke test also points USERPROFILE at a synthetic profile containing only synthetic settings, subscription, history, and style files.

The workflow downloads the official Inno Setup 7.1.0 x64 installer from the immutable jrsoftware/issrc release is-7_1_0. Before executing it, CI verifies the GitHub release attestation with gh release verify-asset and checks that Authenticode is valid with publisher Pyrsys B.V. It installs the compiler under RUNNER_TEMP and compiles installer/KV-Agent-Desk.iss with the version from pyproject.toml.

For a local Setup build, run .\Build-Installer.ps1. It runs Build-Dashboard.ps1 first so an older dist/KV-Agent-Desk.exe cannot be labeled with the current source version. The script stages only the executable, project license, third-party notices, CPython license, and text licenses from locked build dependencies. If Inno Setup 7.1.0 is not already on PATH, the script downloads and verifies the official compiler before installing it under the system temporary directory. GitHub CLI is needed for local release-attestation verification.

The -SkipAppBuild switch is reserved for CI after a fresh executable build. The workflow uses that switch to avoid rebuilding the executable twice and passes the verified ISCC.exe path. Do not use the switch with a stale dist/KV-Agent-Desk.exe.

The Setup wizard is a current-user x64 install. Its directory page defaults to D:\APP\KV-Agent-Desk, then reads a valid userhome/.kv-agent-desk/installation.ini installation record before the HKCU mirror or the default directory. Setup keeps the directory page visible, creates a Start Menu entry, and checks desktop shortcut and auto-start tasks on first installation. Later Setup runs retain the selected task choices. Desktop, Start Menu, and sign-in launch commands bind to the canonical .kv-agent-desk state directory. Inno Setup tracks the Start Menu and optional desktop shortcuts from its [Icons] section and removes those links during uninstall. The runtime uninstall hook stops the app, removes its auto-start registration, and clears matching installation metadata before Inno removes the tracked program files. The application, settings, style copies, subscription data, history, and cache remain separate; Setup and uninstall never recursively delete user data.

The Setup package contains the clean KV-Agent-Desk.exe, LICENSE, THIRD_PARTY_NOTICES.md, and text license files for CPython and locked build dependencies. The executable embeds only the existing five public runtime assets: app.ico, deepseek.png, chatgpt.png, glm.png, and google.png. The build does not package runtime/, local settings, keys, subscription contents, or private logos.

The portable Windows ZIP remains available with the same executable and public notices. The raw KV-Agent-Desk.exe, its SHA-256 sidecar, KV-Agent-Desk.update.json, and the ZIP retain their existing names and update protocol for compatibility with older clients. A tagged release additionally publishes KV-Agent-Desk-Setup.exe and its SHA-256 sidecar. The update manifest continues to describe only the raw EXE and its checksum, with fixed release URLs.

The build job has read-only repository permissions and no user-provided secrets. The release job uses the built-in GITHUB_TOKEN with contents: write only to publish the tag release. PyInstaller bytecode may contain co_filename source paths; CI builds from the public GitHub checkout.
